# JNF — Japanese Notation Fidelity（日本語表記の忠実度）

企画書 §18 の JNF を、v0.1 で実装する形に固定する（#230。実装は #231）。
**JNF は「読めた文字のうち、表記（全角/半角・丸数字・旧字体・△ など）まで原本どおりか」を測る**。
文字の欠落・誤認識は CF の領域で、JNF では数えない。v0.1 では **Total に入れず、別の列として公開する**。

## 測り方

1. GT と出力それぞれの `Document.text()`（CF と同じ比較対象）から空白類（`\s` と U+3000。改行を含む）を除き、`g` / `d` とする
2. `rapidfuzz.distance.Levenshtein.opcodes(g, d)` で整列する（editops と同じ整列を区間単位で受け取る）
3. 区間ごとに数える。**表記対象文字**は下の「文字クラス」に入る文字
   - `equal` 区間: 中の表記対象文字を **exact** として数える
   - 連続する `equal` 以外の区間（replace / insert / delete）は 1 つの**差分区間**にまとめる。
     `fold(GT 側) == fold(出力側)` なら、区間内の表記対象文字を **folded**（表記置換）として数える。
     `⑴` ↔ `(1)`、`ｶﾞ` ↔ `ガ` のように fold で長さが変わる差を拾うため
   - 差分区間の fold が一致しなければ、replace の文字対 (a, b) ごとに見る。`fold(a) == fold(b)` で、どちらかが表記対象文字なら folded
   - 上記以外（欠落・挿入・fold しても一致しない置換）は数えない（CF の領域）
4. **JNF = 1 − folded / (exact + folded)**（小数 4 桁に丸める。CF などと同じ）

クラスの帰属は **GT 側の文字のクラス、GT 側がどのクラスにも入らなければ出力側の文字のクラス**。
folded を 1 区間で数える数も同じ規則で、GT 側の表記対象文字の数（無ければ出力側の数）とする。

## 文字クラス

| クラス | 対象（コードポイント） | 例 |
|---|---|---|
| `fullwidth-alnum` | U+FF10–FF19、U+FF21–FF3A、U+FF41–FF5A | `１` `Ａ` `ｏ` |
| `fullwidth-symbol` | U+FF01–FF5E のうち上記以外、U+FFE0–FFE6 | `（` `，` `％` `－` `～` `￥` |
| `enclosed` | U+2460–24FF、U+2776–2793、U+3251–325F、U+32B1–32BF、U+2160–217F（ローマ数字） | `①` `⑴` `Ⅲ` |
| `halfwidth-kana` | U+FF61–FF9F（半角カナと半角の約物） | `ｶ` `ﾞ` `｢` |
| `kyujitai` | fold の旧字体表のキー | `國` `縣` `廣` |
| `negative-mark` | `△` `▲` `∆`（U+2206）`▵` `▴` | `△ 733` |
| `ditto` | `〃` `″`（U+2033） | `〃` |

ローマ数字は NFKC で英字に分解される「数字の字形」なので `enclosed` に入れる（クラスを増やさない）。
どのクラスにも入らない NFKC 互換文字（`︓` などの縦書き用の約物）は、相手側がクラス文字のときだけ数える。

## fold

`fold(s)` = 次の 3 段を順に適用した文字列。比較だけに使い、出力や GT は書き換えない。

1. 記号の異体表: `▲` `∆` `▵` `▴` → `△`、`″` → `〃`（NFKC では畳まれないため。`″` は NFKC で `′′` に分解されるので NFKC より先に置く）
2. NFKC
3. 旧字体 → 新字体の表（estat の GT に出る字から）: `國→国 縣→県 體→体 齡→齢 關→関 當→当 區→区 觀→観 帶→帯 收→収 囘→回 總→総 萬→万 繩→縄 兒→児 廣→広 靜→静 內→内`。
   表は GT に新しい旧字体が出たときだけ足す（足すと値が動くので、足した版を記録する）

## 判断

- **出力側だけにある表記差も数える**（GT が `(` で出力が `（`、GT が `県` で出力が `縣`）。
  GT 側だけを見ると「全部を全角にする」パーサーが、GT が半角の文書で減点されない。
  分母には GT の半角英数字すべてではなく、その表記置換が起きた文字だけが入るので、数字の多い文書でも JNF が 1.0 に薄まらない。
  試算でも ppstructure が GT の半角 `%` `(` `)` などを全角で出す例が 58 件、pymupdf にも 2 件ある
- **欠落は分母に入れない**。読めなかった文字は CF が減点する。JNF は「読めた範囲の表記」に限る（両方で二重に減点しない）
- `‐` と `−`、`，` と `、`、`－` と `一` のように **NFKC と上の表で畳まれない差は表記差としない**（CF の領域）。
  試算では OCR 系の `，` → `、`（86 件）が多いが、句読点の流儀か誤認識かを文字だけで区別できないため v0.1 では入れない

## 除外と None

- **除外**: 空白類と改行（手順 1 で除く。字送りの空白は CF の領域）。
  **縦中横**: GT の block の `extra.writing_mode` が `"vertical"` なら、そのブロックの英数字（ASCII と全角）の位置を exact / folded の両方から除く（差分区間に除外位置を含むときは、区間単位の判定をせず文字対の判定だけにする）。
  除外位置は内訳の `gt`（GT 側のクラス文字の数）にも数えない。
  縦書きの英数字は、全角の正立と縦中横（半角 2〜3 字を 1 字分に収めたもの）が印字で区別できず、GT が正しい表記を決められないため（#233 の官報 GT で付ける）
- **None**: GT のテキストが空、または exact + folded = 0（整列した表記対象文字が無い。テキスト層の無いスキャンを OCR なしで読んだ出力など）。
  分母が小さいときは値が粗いので、内訳で分母を一緒に出す

## Total との関係・出力

v0.1 では **Total に入れない**。`evaluate` は `jnf`（値）と `jnf_classes`（クラスごとの `{gt, exact, folded}`）を返し、
report / summary では Total の隣に別の列として出す。`gt` は GT 側のクラス文字の数（整列前）、
`exact` / `folded` は上の規則の数で、出力側だけの表記差を含むため `folded` が `gt` を超えることがある。

## 既知の揺れ（kanpo × markitdown）

官報（`kanpo-20261020-h1811-excerpt`）の markitdown は、コードを変えていない run の間で JNF が 0.81〜0.93 で揺れる（CF・ROA も小さく揺れる。Total は丸めると変わらない）。
原因は pdfminer の `group_textboxes` で、テキストボックスを結合する順序をヒープの同点のとき `id()`（メモリアドレス）で決めている。
縦書きは 1 文字 1 行になり距離の同点が多いため、プロセスごとに出力順が変わる（`PYTHONHASHSEED` を固定しても止まらない）。
決定的にするにはパーサーの設定を変える必要があり、特定のパーサーに手を入れない方針に反するので直さない（jdoc-bench#267）。
